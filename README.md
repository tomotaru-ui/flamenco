# フラメンコ公演 参加登録システム

Carlos Gomez Flamenco School 主催のフラメンコ公演(2027年11月21日・那覇市ぶんかテンプス館 4階テンプスホール、定員220名)向けの、参加登録・チケット管理システムです。

- 参加登録フォーム(GitHub Pages): `index.html`
- 受付QRチェックイン(GitHub Pages / スタッフ用): `checkin.html`
- バックエンド(Google Apps Script + Google スプレッドシート): `apps-script/`

## 全体の仕組み

1. 参加者が `index.html` のフォームから登録すると、Google Apps Script(GAS)が
   - 定員(220名)を超えていないかチェック
   - スプレッドシートに1行追加(登録番号・氏名・人数・金額・支払方法などを記録)
   - QRコード(登録番号を署名付きで暗号化した文字列)を生成
   - 参加者にQRコード付きの確認メールを送信
2. 当日、スタッフが `checkin.html` でQRコードをスキャンすると、登録内容と支払状況が表示され、
   - 「支払い確認済みにする」→ 現金受領時や、口座振込を確認できたときに押す
   - 「入場受付する」→ 入場時に押す
3. 口座振込の場合、振込名義の先頭に登録番号(下4桁)を入力してもらうことで、通帳・オンラインバンキングの入金一覧とスプレッドシートの登録番号を照合できます。支払い確認はスタッフが手動で行います(自動連携はしていません)。

6. エディタ上部の関数選択で `setup` を選び、実行します。初回はGoogleアカウントへのアクセス許可を求められるので許可してください(スプレッドシートへのアクセス・メール送信権限など)。実行後、スプレッドシートに「登録」シートとヘッダー行が作成されます。
7. 右上の「デプロイ」→「新しいデプロイ」をクリックします。
   - 種類の選択:「ウェブアプリ」
   - 説明:任意(例:`v1`)
   - 実行するユーザー:「自分(okinawakarate2026@gmail.com)」
   - アクセスできるユーザー:「全員」
   - 「デプロイ」をクリックし、表示された **ウェブアプリのURL(`https://script.google.com/macros/s/.../exec`)** をコピーします。
8. コピーしたURLを [`assets/config.js`](assets/config.js) の `GAS_URL` に貼り付けます。

```js
const GAS_URL = "https://script.google.com/macros/s/ここに実際のID/exec";
```

9. コードを変更のたびに再デプロイする場合は「デプロイ」→「デプロイを管理」→ 既存のデプロイの編集(鉛筆アイコン)→ バージョン「新バージョン」を選んで更新してください(URLは変わりません)。

## GitHub Pages の公開設定

このリポジトリ(`tomotaru-ui/flamenco`)の GitHub 設定画面から:

1. `Settings` → `Pages`
2. `Source` を `Deploy from a branch` にし、Branch を `main` / `root` に設定して保存

数分後、`https://tomotaru-ui.github.io/flamenco/` で `index.html`(参加登録ページ)が公開されます。スタッフ用チェックインページは `https://tomotaru-ui.github.io/flamenco/checkin.html` です。

> チェックインページはURLを知っていれば誰でも開けますが、スタッフPIN(`STAFF_PIN`)を知らないとデータの閲覧・更新はできません。PINは受付スタッフ内のみで共有してください。

## 運用フロー

### 参加登録(参加者側)
1. `index.html` で氏名・メール・人数・支払方法を入力して送信
2. 定員に空きがあれば登録完了、なければ「満席」の案内が表示される
3. 登録したメールアドレスにQRコード付き確認メールが届く(振込の場合は口座情報・登録番号の入力方法も記載)

### 支払い確認(スタッフ側・イベント前)
- 口座振込の入金一覧(依頼人名の先頭4桁が登録番号)とスプレッドシートを突き合わせ、該当者の「支払状況」列を「確認済」に更新するか、`checkin.html` で登録番号を検索して「支払い確認済みにする」を押す

### 当日受付(スタッフ側)
1. `checkin.html` を開き、PINを入力
2. 参加者のQRコードをカメラでスキャン(または登録番号を手入力して検索)
3. 氏名・人数・支払状況が表示されるので確認
4. 現金払いでまだ未確認の場合は、集金後に「支払い確認済みにする」を押す
5. 「入場受付する」を押して入場記録を更新

## スプレッドシートの列構成(自動生成される「登録」シート)

| 列 | 内容 |
|---|---|
| 登録番号 | `TF-0001` のような連番。QRコードの元になる |
| タイムスタンプ | 登録日時 |
| 代表者氏名 / フリガナ / メールアドレス / 電話番号 | 入力内容 |
| 大人人数 / 子供人数 | 入力内容 |
| 合計金額 | 自動計算(大人2,500円・子供1,000円、税込) |
| 支払方法 | 「口座振込」または「当日現金」 |
| 支払状況 | 「未確認」→ スタッフが確認後「確認済」 |
| 入場チェック | 「未」→ 受付通過後「済」 |
| 備考 | 自由記入用(手動で使用) |

## セキュリティ上の注意

- QRコードには登録番号 + 署名(`QR_SECRET` によるHMAC)が入っており、単純な連番の推測だけでは他人のQRコードを偽造できません。
- チェックイン・支払確認・一覧表示のAPIは全て `STAFF_PIN` による認証が必須です。PINは推測されにくい値にし、定期的に変更することをおすすめします。
- 振込口座情報は `BANK_OKINAWA` / `BANK_RYUKYU` のスクリプトプロパティで管理しているため、確定後はコードを変更せずに値を更新するだけで反映されます(再デプロイ不要、次回送信メールから即反映)。
